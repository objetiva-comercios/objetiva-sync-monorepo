  <name>Task 2: Create Prisma model generator with BigInt handling and annotation preservation</name>
  <files>
    objetiva-sync-gateway/src/codegen/prisma-generator.ts

  <action>
    Create `src/codegen/prisma-generator.ts` that generates the complete schema.prisma file content from schema metadata.

    **Critical design decisions for pitfall avoidance:**

    1. **BigInt detection (Pitfall 2):** The introspection normalizes `bigint` to `int`. The generator MUST detect BigInt columns using these heuristics:
       - Column named exactly `id` (the autoincrement PK) -> BigInt
       - Column ending with `_id` (FK references to BigInt PKs) -> BigInt
       - All other `int` type columns -> Int
       This is a known-column-pattern heuristic (Research open question 2, option b).

    2. **@db.* annotations (Pitfall 1):** Map normalized types back to Prisma decorators:
       - `text` -> `String @db.Text`
       - `decimal` -> `Decimal @db.Decimal(p, s)` - Extract precision/scale from `default_value` or column metadata. The introspection returns `numeric_precision` and `numeric_scale` in ColumnMetadata via `data_type` field. IMPORTANT: The current ColumnMetadata does NOT include precision/scale. Use heuristic based on existing schema patterns: detect from column context. For now, use a COLUMN_PRECISION_MAP constant with known columns and their precision/scale values extracted from existing schema.prisma. Unknown decimal columns default to `@db.Decimal(10, 2)`.
       - `timestamp` -> `DateTime @db.Timestamp(6)`
       - `jsonb` -> `Json @db.JsonB`
       - `array` -> `String[] @db.Text` (arrays in existing schema are text arrays)
       - `boolean` -> `Boolean` (no @db annotation needed)
       - `int` -> `Int` or `BigInt` (per BigInt detection above)
       - `uuid` -> `String @db.Uuid`

    3. **@map column mappings (Pitfall 4):** Parse the EXISTING schema.prisma file to extract current field-to-column @map directives. Build a Map<string, Map<string, string>> (table -> column_name -> prisma_field_name). When generating, if a column has a known @map entry, use the Prisma field name and add `@map("db_column_name")`. New columns (not in existing map) use the database column name directly.

    4. **Relation directives (Pitfall 3):** From FK constraints, generate:
       - The scalar FK field (already in columns, e.g., `comprobante_id BigInt?`)
       - A relation field: `comprobante ComprobanteCabecera? @relation(fields: [comprobante_id], references: [id], onDelete: Cascade)`
       - On the referenced model, a reverse relation: `detalles ComprobanteDetalle[]`
       Build a RELATION_CONFIG constant that maps FK constraint patterns to relation names. Use known relations from existing schema.prisma.

    5. **@@map table mapping:** Map entity name to Prisma model name. Build MODEL_NAME_MAP: `{ articulos: 'Articulo', comprobantes_cabecera: 'ComprobanteCabecera', comprobantes_detalle: 'ComprobanteDetalle', comprobantes_pagos: 'ComprobantePagos' }`.

    6. **@@index directives:** Extract from existing schema.prisma. Store as INDEX_CONFIG per model. Indexes are structural and don't change with column introspection.

    7. **@@unique constraints:** Extract from ConstraintMetadata where constraint_type is 'UNIQUE'. Generate @@unique directives.

    **Main function:**
    `generatePrismaSchema(schemas: SchemaResponse[]): string`

    Implementation approach:
    - Read existing schema.prisma to extract: @map mappings, relations, indexes (parse statically at generation time)
    - Generate the header (generator + datasource blocks - KEEP UNCHANGED from existing file)
    - For each entity/schema: generate model block with fields, annotations, relations, indexes, @@map
    - Return complete schema.prisma content as string

    **Helper functions:**
    - `parseExistingSchema(content: string): ExistingSchemaInfo` - Extracts @map directives, relation fields, indexes from current schema.prisma text
    - `mapToPrismaType(col: ColumnMetadata, tableName: string): PrismaFieldConfig` - Maps column to Prisma type with BigInt detection and @db annotation
    - `generatePrismaField(col: ColumnMetadata, tableName: string, existingMaps: Map<string, string>): string` - Full field line with type, nullability, default, @db, @map
    - `generateModelBlock(schema: SchemaResponse, existing: ExistingSchemaInfo): string` - Complete model block

    **IMPORTANT:** The generator should preserve the EXISTING schema.prisma header (generator/datasource blocks) and comments. Only regenerate the model blocks. Read the existing file, split at the first `model` keyword, keep everything before it, then append generated models.

    **IMPORTANT:** Do NOT generate the `@id @default(autoincrement())` annotation by trying to detect it from ColumnMetadata. Instead, check if the column is part of a PRIMARY KEY constraint (from ConstraintMetadata) and if the default_value contains 'nextval' (indicating autoincrement).
  </action>

  <name>Task 3: Create Zod schema generator for database-structure-only schemas</name>
  <files>
    objetiva-sync-gateway/src/codegen/zod-generator.ts
  </files>
  <action>
    Create `src/codegen/zod-generator.ts` that generates per-entity Zod schema files reflecting DATABASE structure only (types + nullability), NOT business logic.

    **Key design decision (Pitfall 5):** Generated Zod schemas go to `shared/schemas/generated/{entity}.generated.ts`. These are separate from the hand-written schemas in `shared/schemas/{entity}.ts` which contain business rules (.min(), .positive(), .describe(), .enum()). The hand-written schemas can later be refactored to import and extend the generated base schemas, but that is NOT part of this phase.

    **Main function:**
    `generateZodSchema(schema: SchemaResponse): string`

    Returns the complete file content for a single entity's generated Zod schema.

    **Type mapping (normalized introspection type -> Zod validator):**
    - `text`, `varchar`, `char` -> `z.string()`
    - `int` -> `z.number().int()` (same for both Int and BigInt in Zod - JS numbers)
    - `float` -> `z.number()`
    - `decimal` -> `z.number()` (Zod doesn't have Decimal; use number)
    - `boolean` -> `z.boolean()`
    - `timestamp`, `date`, `time` -> `z.coerce.date()` (coerce handles string/Date input)
    - `jsonb` -> `z.record(z.unknown())` (not z.any() - use unknown for safety)
    - `uuid` -> `z.string().uuid()`
    - `array` -> `z.array(z.string())` (all current arrays are text arrays)
    - Default/unknown -> `z.string()`

    **Nullability:**
    - If `is_nullable === true` -> append `.nullable().optional()`
    - If `is_nullable === false` -> no modifier (required)

    **Default values:**
    - If column has a default_value, do NOT make the field required in the Zod schema. Add `.optional()` regardless of nullability since the DB will provide the default.
    - Exception: `id` column - skip entirely from generated Zod schema (autoincrement PK, not part of input validation)
    - Exception: `creado`/`actualizado` timestamp columns with `now()` defaults - skip from generated schema (managed by DB/Prisma)

    **File content structure:**
    ```typescript
    // Auto-generated from PostgreSQL schema introspection
    // DO NOT EDIT - regenerate with: npm run regenerate-schemas
    // Generated: {ISO timestamp}

    import { z } from 'zod';

    /**
     * Database-structure schema for {entity}
     * Reflects PostgreSQL column types and nullability only.
     * For business validation rules, see shared/schemas/{entity}.ts
     */
    export const {EntityName}DbSchema = z.object({
      // ... fields
    });

    export type {EntityName}DbInput = z.infer<typeof {EntityName}DbSchema>;
    ```

    **Entity naming:** Convert snake_case table name to PascalCase for the schema name:
    - `articulos` -> `ArticulosDbSchema`
    - `comprobantes_cabecera` -> `ComprobantesCabeceraDbSchema`
    - etc.

    **Helper functions:**
    - `mapToZodType(col: ColumnMetadata): string` - Returns Zod validator string
    - `shouldSkipColumn(col: ColumnMetadata): boolean` - Returns true for id, creado, actualizado columns
    - `toPascalCase(snakeCase: string): string` - Converts entity name to PascalCase
    - `generateZodField(col: ColumnMetadata): string` - Full field line with type and nullability

    **Ensure the `shared/schemas/generated/` directory is created** by the orchestrator (Plan 02), not by this generator. The generator only produces string content.
  </action>
