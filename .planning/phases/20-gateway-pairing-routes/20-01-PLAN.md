<feature>
  <name>Pairing Code Store</name>
  <files>objetiva-sync-gateway/src/lib/pairing-store.ts, objetiva-sync-gateway/tests/unit/pairing-store.test.ts</files>
  <behavior>
    - generateCode() returns { code: string, expiresAt: Date } where code is 6 chars from ABCDEFGHJKLMNPQRSTUVWXYZ23456789
    - generateCode() invalidates any previous active code (only one active at a time)
    - claimCode(input) returns 'ok' for valid active code
    - claimCode(input) returns 'consumed' for already-claimed code (enables 410 response)
    - claimCode(input) returns 'invalid' for unknown or expired code (enables 404 response)
    - claimCode normalizes input to uppercase (case-insensitive matching)
    - Expired codes are cleaned up via setTimeout with .unref() (no process hang)
    - Consumed codes Set is bounded — auto-cleaned after TTL + 5s buffer
    - _resetForTest() clears all state for test isolation
  </behavior>
  <implementation>
    Module-level singleton with:
    - `let activeEntry: PairingEntry | null` — one active code at a time
    - `const consumedCodes = new Set<string>()` — for 410 vs 404 distinction
    - `CHARSET = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'` (32 chars, 256 % 32 === 0, no modulo bias)
    - `CODE_LENGTH = 6`, `TTL_MS = 10 * 60 * 1000`
    - `crypto.randomBytes(CODE_LENGTH)` for secure generation
    - All setTimeout handles call `.unref()` to prevent process hang in tests
    - Export `_resetForTest()` that clears activeEntry, consumedCodes, and any pending timers
  </implementation>
</feature>
