     - Parse DATABASE_URL from environment (same as Prisma uses)
     - Set statement_timeout: 5000 (5 seconds per context decisions)
     - Set max: 5 (small pool, introspection queries are infrequent)
     - Set idleTimeoutMillis: 30000

   - Add graceful shutdown handler (process.on beforeExit)

2. Create `src/lib/retry.ts`:
   - Import backOff from 'exponential-backoff'
   - Import logger from './logger.js'
   - Create `withRetry<T>(operation: () => Promise<T>, operationName: string): Promise<T>`
   - Configure backOff with:
     - numOfAttempts: 3
     - startingDelay: 1000 (1s)
     - timeMultiple: 2 (exponential: 1s, 2s, 4s)
     - jitter: 'full'
   - Add retry predicate that ONLY retries connection errors:
     - ECONNREFUSED, ETIMEDOUT, ENOTFOUND, ECONNRESET
     - Log each retry attempt with operation name
   - Do NOT retry on: SQL syntax errors, permission errors, query timeouts

Avoid:
- Do NOT create global pool in module scope that connects immediately
- Do NOT use generic retry logic for all errors (per Research pitfall #7)
