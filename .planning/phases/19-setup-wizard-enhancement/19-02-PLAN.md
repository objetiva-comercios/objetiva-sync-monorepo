  <files>objetiva-sync-gateway/src/routes/setup.ts</files>
  <action>
    Replace ONLY the HTML string inside `app.get('/setup', ...)` handler (lines ~20-725). Keep all API route handlers below it unchanged.

    **Step state machine (vanilla JS inside the HTML script tag):**
    ```javascript
    const state = {
      currentStep: 0,
      completedSteps: new Set(),
      stepData: {}
    }
    ```

    **5 steps to implement:**

    **Step 0 — Database (WIZ-02):**
    - 5 separate input fields: host (text, placeholder "localhost"), port (text, default "5432"), user (text), password (password), database name (text)
    - "Test Connection" button calls `assembleDbUrl()` client-side then POSTs to `/api/setup/test-db` with `{ databaseUrl }`
    - On success: show table check results as info (if `tables` field in response). Mark step complete, advance
    - On failure: show error message in a red alert, stay on step
    - `assembleDbUrl()`: `postgresql://${encodeURIComponent(user)}:${encodeURIComponent(pass)}@${host}:${port}/${dbName}`
    - Do NOT include password in stepData (clear after successful test)

    **Step 1 — Domain (WIZ-03):**
    - Protocol dropdown: `<select>` with options "https" (default) and "http"
    - Domain text input (placeholder "gateway.example.com")
    - Port field: hidden by default, show via "Advanced" toggle. Placeholder: "leave empty for default"
    - "Save & Next" button POSTs to `/api/setup/save-domain` with `{ protocol, domain, port }`
    - "Skip (not recommended)" button: shows warning alert "Without a public URL, pairing won't work", marks `stepData.domainSkipped = true`, advances without backend call
    - On success: advance. On 400: show validation error, stay on step
    - Default port omission: if port matches protocol default (443/https, 80/http) or is empty, omit from payload

    **Step 2 — JWT Secret (WIZ-04):**
    - Text input for JWT secret (type="text" so operator can see it)
    - "Generate JWT Secret" button: `crypto.getRandomValues(new Uint8Array(32))` -> hex string (64 chars), fills the input
    - Min 32 chars validation client-side before calling backend
    - "Save & Next" button POSTs to `/api/setup/save-jwt-secret` with `{ jwtSecret }`
    - On success: advance. On error: show message, stay

    **Step 3 — Password:**
    - Info text: "Username: admin (fixed)"
    - Password input (type="password"), min 6 chars client-side validation
    - "Save & Next" button POSTs to `/api/setup/set-password` with `{ password }`
    - On success: advance. On error: show message, stay

    **Step 4 — Download (WIZ-05, WIZ-06):**
    - Re-fetch `GET /api/setup/status` on entering this step to show current configuration summary
    - Summary: database host/port/db (no password), gateway URL (or "Not configured" warning if skipped), JWT preview, auth username + "configured" badge
    - If domain was skipped: show yellow warning box about pairing
    - "Download .env" button: `window.location.href = '/api/setup/generate-env'`
    - "Restart the server to apply all changes" instruction text
    - No "Next" button — this is the final step

    **Progress indicator:**
    - Numbered stepper at top: "Step 1 of 5 — Database" etc.
    - Use dots or numbered circles: completed = filled/green, current = outlined/blue, upcoming = gray

    **Navigation:**
    - "Next" / "Test Connection & Next" / "Save & Next" — calls backend, advances on success only (WIZ-01 gating)
    - "Back" button on steps 1-4 — always enabled, goes to previous step without validation
    - No "Back" on step 0 (first step)

    **Pre-fill on load:**
    ```javascript
    window.addEventListener('DOMContentLoaded', async () => {
      const [preflight, status] = await Promise.all([
        fetch('/api/setup/preflight').then(r => r.json()),
        fetch('/api/setup/status').then(r => r.json())
      ])
      // Pre-fill DB fields from status.database if present
      if (status.database) {
        document.getElementById('db-host').value = status.database.host
        document.getElementById('db-port').value = status.database.port
        document.getElementById('db-user').value = status.database.username
        document.getElementById('db-name').value = status.database.database
        // password field stays empty — show "[configured]" placeholder
      }
      // Pre-fill domain from status.gatewayUrl
      if (status.gatewayUrl) {
        try {
          const url = new URL(status.gatewayUrl)
          document.getElementById('domain-protocol').value = url.protocol.replace(':', '')
          document.getElementById('domain-input').value = url.hostname
          if (url.port) document.getElementById('domain-port').value = url.port
        } catch {}
      }
      // JWT: show "configured" indicator if status.jwt exists
      if (status.jwt) {
        document.getElementById('jwt-configured').style.display = 'block'
        document.getElementById('jwt-configured').textContent = `Currently configured (${status.jwt.length} chars): ${status.jwt.preview}`
      }
    })
    ```

    **Styling:**
    - Keep existing CSS approach (inline styles in the HTML string)
    - Keep the existing gradient background, white container card, rounded corners, shadow
    - Add wizard-specific styles: step hidden by default (`display: none`), active step shown
    - Alert styles: `.alert-error` (red bg), `.alert-warning` (yellow bg), `.alert-success` (green bg)
    - Progress dots: flexbox row, circles with numbers
    - Buttons: keep existing blue primary style, add gray secondary for Back, orange for Skip

    **XSS prevention:**
    - Use `element.textContent = value` for all user-provided strings in alerts/summaries
    - Reserve `innerHTML` only for trusted static strings (spinner HTML, step structure)

    **Important:** The HTML string is a template literal inside the route handler. Keep it as one continuous string. Do NOT try to split it into separate files — that breaks the established pattern per user decision.
