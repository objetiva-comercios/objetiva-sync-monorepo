  <action>
Create `deploy.sh` -- a bash deployment script designed for Windows/Git Bash (but also compatible with native Linux bash). Structure:

1. **Header**: `#!/bin/bash` with `set -euo pipefail`
2. **SCRIPT_DIR detection**: `cd` to script directory so paths are relative to project root
3. **Logging function**: `log()` with timestamp, writes to stdout and `logs/deploy-YYYYMMDD-HHMMSS.log`
4. **Error handler**: `trap 'handle_error $LINENO' ERR`
5. **validate_env_vars function**: Same pattern as gateway -- checks each var is set and non-empty, reports all missing at once
6. **Pre-flight checks**:
   - Node.js version >= 20 (parse `node -v`)
   - `npm` available
   - `pm2` available (with hint: `npm install -g pm2`)
   - No pg_dump check needed (SQLite, not PostgreSQL)
7. **Load and validate environment**:
   - Check `.env` file exists
   - `source .env`
   - `validate_env_vars PORT NODE_ENV DATABASE_PATH`
   - Note: ENCRYPTION_KEY and SESSION_SECRET are auto-generated by the app on first run, so they are NOT required in validation
8. **Install dependencies**: `npm ci --production=false` (need devDeps for tsup)
9. **Build TypeScript**: `npm run build` (uses tsup), verify `dist/` directory exists
10. **Ensure database directory exists**:
    - `mkdir -p "$(dirname "$DATABASE_PATH")"` -- uses the DATABASE_PATH env var for the actual app database
    - `mkdir -p ./database` -- ALSO ensures the `./database/` directory exists because `drizzle.config.ts` hardcodes the SQLite path as `./database/objetiva-sync.db`. This is a KNOWN COUPLING: drizzle-kit reads drizzle.config.ts directly and ignores the DATABASE_PATH env var. Add a comment in the script explaining this coupling: `# KNOWN COUPLING: drizzle.config.ts hardcodes ./database/objetiva-sync.db path. DATABASE_PATH env var is used by the app at runtime, but drizzle-kit uses drizzle.config.ts directly. Both directories must exist.`
11. **Run Drizzle migrations**: `npx drizzle-kit migrate`
12. **Start/reload PM2**:
    - If process `objetiva-sync` already exists: `pm2 reload ecosystem.config.js --env production`
    - Else: `pm2 start ecosystem.config.js --env production`
    - Save: `pm2 save`
13. **Health check**: Sleep 3 seconds, check PM2 process is online
14. **Final log**: "Sync deployment completed successfully"

**Windows/Git Bash compatibility notes** (implement these):
- Use `stat -c%s "$file" 2>/dev/null || stat -f%z "$file" 2>/dev/null || echo "unknown"` if checking file sizes
- Avoid Linux-only commands. `find -mtime` works in Git Bash so it's fine.
- Use `mkdir -p` which works on both
- Do NOT use `readlink -f` (not available in Git Bash) -- use `cd "$(dirname ...)" && pwd` pattern instead

Create `ecosystem.config.js` -- PM2 ecosystem file:
- `name`: "objetiva-sync"
- `script`: "./dist/index.js"
- `instances`: 1
- `exec_mode`: "fork" (NOT cluster -- sync has stateful scheduler, cron jobs, and dashboard sessions)
- `env_production`: `{ NODE_ENV: "production" }`
- `watch`: false
- `autorestart`: true
- `max_memory_restart`: "512M"
- `min_uptime`: "10s"
- `max_restarts`: 10
- `error_file`: "./logs/pm2-error.log"
- `out_file`: "./logs/pm2-out.log"
- `log_date_format`: "YYYY-MM-DD HH:mm:ss Z"
- `merge_logs`: true

IMPORTANT: Do NOT use cluster mode. The sync module has a scheduler (node-cron), stateful sync queue, dashboard sessions, and SQLite (which doesn't support concurrent writes from multiple processes). Fork mode with 1 instance is required.
