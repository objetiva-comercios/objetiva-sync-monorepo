   **Paso 6: Verificacion final — Schema Status**
   Open Schema Status page in gateway dashboard. All columns should show green (aligned) across the 3 layers (PostgreSQL live, gateway compiled, sync reported).
   Verificar: no red or yellow indicators remain per D-09.

3. **Escenarios comunes** — Short callout notes per D-03 (one generic flow, scenario-specific notes):

   - **Columna nueva agregada:** After regeneration, the new column appears in Zod schema and Prisma model. `prisma db push` is a no-op for this column (already in PostgreSQL). If sync sends data for this column, update `objetiva-sync/src/types/*.ts` manually.
   - **Tipo de columna cambiado:** Regeneration updates the Zod type and Prisma `@db.*` annotation. `prisma db push` may show a warning if the change requires data migration. Review carefully.
   - **Columna eliminada:** Regeneration removes the field from Zod and Prisma. `prisma db push` with `--accept-data-loss` (already in entrypoint) will drop the column from Prisma's perspective. PostgreSQL column was already dropped.
   - **Tabla nueva agregada:** Requires adding the entity to the gateway introspection endpoints and regeneration script entity list before running the procedure. This is a code change, not just a regeneration.

4. **Ejemplo de dry-run** per D-04 — A representative example showing a new column added to articulos:
   ```
   === articulos ===
   + stock_minimo: integer, nullable

   Resumen: 1 campo agregado en 1 entidad
   ```

5. **Troubleshooting** per D-08 — 4-5 FAQ entries:

   - **"JWT authentication failed" al ejecutar el script:** Verify JWT_SECRET in root `.env` matches the gateway's JWT_SECRET. Check GATEWAY_URL points to the correct host.
   - **El contenedor no refleja los cambios despues de rebuild:** Verify `git pull` was run on the VPS before `docker compose build`. Check that `--no-cache` flag was used. Verify entrypoint logs show "Schema sync complete."
   - **`prisma db push` falla con error de tipos:** A column type change may be incompatible (e.g., text to integer with existing data). Resolve in PostgreSQL first, then re-run the cycle.
   - **Dry-run no muestra cambios esperados:** The script compares against local files. If local files are already up to date, no diff is shown. Verify the PostgreSQL change was actually applied on the remote database.
   - **Schema Status muestra amarillo/rojo despues del ciclo completo:** Sync may not have reported its schemas yet. Wait for the next sync cycle or restart objetiva-sync. If still mismatched, verify sync is running the latest code with the regenerated schemas.
