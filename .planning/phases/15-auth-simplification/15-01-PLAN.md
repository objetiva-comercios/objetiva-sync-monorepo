<task type="auto">
  <name>Task 1: Add Token Refresh Endpoint</name>
  <files>objetiva-sync-gateway/src/routes/auth.ts</files>
  <action>
Add POST /auth/refresh endpoint to auth.ts that:

1. Verifies the current token using request.jwtVerify() - token may be near expiration but still valid
2. Extracts username from the verified token payload
3. Signs a new JWT with same claims but fresh expiration
4. Returns response with:
   - success: true
   - token: newToken
   - expiresIn: number (seconds until expiry, from JWT_EXPIRES_IN env var, default 3600)
   - issuedAt: ISO timestamp
   - tokenType: 'Bearer'

Also update the login endpoint to include expiresIn in its response so clients know token lifetime.

Handle the case where token is already expired - return 401 with error code TOKEN_EXPIRED and message asking to re-login.

Use the existing JWT_EXPIRES_IN env var parsing (or default to '1h'). Parse duration string to seconds for the response.

Error response format:
```typescript
{
  success: false,
  error: 'TOKEN_EXPIRED',
  message: 'Token expired, please login again'
}
```
  </action>
  <verify>
Run curl commands to test:
```bash
# First login to get a token
curl -X POST http://localhost:3335/auth/login -H "Content-Type: application/json" -d '{"username":"admin","password":"test"}' | jq .

# Then refresh the token
curl -X POST http://localhost:3335/auth/refresh -H "Authorization: Bearer $TOKEN" | jq .
```
Both should return success with token and expiresIn field.
  </verify>
  <done>

Login response includes expiresIn field.

2. Update the authenticate function to:
   - Check for missing Authorization header first, return TOKEN_MISSING

     - FST_JWT_AUTHORIZATION_TOKEN_EXPIRED -> TOKEN_EXPIRED
     - FST_JWT_AUTHORIZATION_TOKEN_INVALID -> TOKEN_INVALID
     - FST_JWT_NO_AUTHORIZATION_IN_HEADER -> TOKEN_MISSING
   - Include specific message in response

3. Response format:
```typescript
{
  success: false,
  error: 'TOKEN_EXPIRED', // The error code
  message: 'Token has expired - refresh or login again'
}
```

4. Log the error code for debugging but not the token itself.

Replace the generic "Token invalido o expirado" message with specific error codes.
