Test cases:

1. `it('should report missing required fields')`:
   - Create query config missing required field (e.g., 'erp_codigo')
   - Validate against schema
   - Assert error includes:
     - Field name that's missing
     - Error type: 'missing_required'
     - Severity: 'error'

2. `it('should report unexpected extra fields')`:
   - Create query config with extra field not in schema (e.g., 'nonexistent_field')
   - Validate against schema
   - Assert error includes:
     - Field name: 'nonexistent_field'
     - Error type: 'unexpected_field'
     - Suggested alternatives (if typo detected)

3. `it('should suggest similar field names for typos')`:
   - Create query with 'sku_codigo' (typo of 'sku' or 'erp_codigo')
   - Validate against schema
   - Assert suggestion includes correct field name
   - Verify Levenshtein distance <= 3 triggers suggestion

4. `it('should report type mismatches')`:
   - Create mapping where source is number but target expects string
   - Validate
   - Assert error includes type mismatch details

5. `it('should format errors for dashboard display')`:
   - Generate validation errors
   - Verify error structure matches dashboard expectations:
     ```typescript
     {
       field: string,
       error: string,
       type: 'missing' | 'extra' | 'type_mismatch' | 'typo',
       suggestion?: string
     }
     ```
