  <name>Task 1: Create schema cache service with 1-hour TTL</name>
  <files>objetiva-sync-gateway/src/services/schema-cache.ts</files>
  <action>
Create an in-memory cache module using a simple Map with TTL expiration.

**Implementation details:**

1. Define a `CacheEntry<T>` interface with `data: T` and `expiresAt: number` fields.

2. Create a `Map<string, CacheEntry<unknown>>` as the internal store. Use module-scoped variable (not class) since this is a singleton cache.

3. Set `TTL_MS = 60 * 60 * 1000` (1 hour) as a constant. This satisfies requirement SCHEMA-04.

4. Export a `schemaCache` object with these methods:
   - `get<T>(key: string): T | null` -- Returns cached data if not expired. If entry exists but is expired, deletes it and returns null. Logs cache expiration at debug level.
   - `set<T>(key: string, data: T): void` -- Stores data with `expiresAt = Date.now() + TTL_MS`. Logs cache set at debug level.
   - `invalidate(key?: string): void` -- If key provided, deletes that entry. If no key, clears entire cache. Logs invalidation at info level. (This is for future use by Phase 3's regeneration command.)
   - `size(): number` -- Returns current number of entries in the cache.

5. Import `logger` from `../lib/logger.js` for logging.

**Important:** Do NOT use a class -- use a plain exported object. This keeps it simple and matches the singleton pattern needed (one cache per process).

**File 1: src/routes/schemas.ts**

Create route registration function following the exact pattern from `articulos.ts`:

```
import type { FastifyInstance } from 'fastify';
import { authenticate } from '../middleware/auth.js';
import { IntrospectionService } from '../services/introspection.js';
import { getSyncEntities } from '../config/entities.js';
import { schemaCache } from '../services/schema-cache.js';
import { logger } from '../lib/logger.js';
```

1. Export `async function registerSchemaRoutes(app: FastifyInstance)`.

2. Register `app.get('/api/schemas/:entity', { preHandler: authenticate }, async (request, reply) => { ... })`.

3. Inside the handler:

   a. Extract entity: `const { entity } = request.params as { entity: string };`

   b. **Validate entity** against allowed list:
      ```
      const allowedEntities = getSyncEntities();
      if (!allowedEntities.includes(entity)) {
        return reply.status(404).send({
          error: `Entity not found: ${entity}`,
          code: 'ENTITY_NOT_FOUND',
        });
      }
      ```

   c. **Check cache** first:
      ```
      const cached = schemaCache.get(entity);
      if (cached) {
        reply.header('X-Cache', 'HIT');
        reply.header('Cache-Control', 'public, max-age=3600');
        return cached;
      }
      ```
      Cache the MAPPED response object (with `entity` field), not the raw TableSchema (which has `table_name`).

   d. **Cache miss -- introspect from database:**
      Wrap in try/catch. On success:
      - Call `IntrospectionService.introspectTable('public', entity)`
      - Map response to API contract: `{ entity: tableSchema.table_name, columns: tableSchema.columns, constraints: tableSchema.constraints }` -- **omit** `table_comment` per context decision (response is `{ entity, columns, constraints }` only)
      - Store mapped response in cache: `schemaCache.set(entity, response)`
      - Set headers: `X-Cache: MISS`, `Cache-Control: public, max-age=3600`
      - Return the mapped response

   e. **On error:**
      - Extract error message and code (use same pattern as introspection.ts error handling)
      - Log with `logger.error({ entity, error: message }, 'Schema introspection failed')`
      - Return 500 with detailed error format:
        ```
        {
          error: `Failed to introspect entity: ${entity}`,
          code: errorCode,    // e.g., 'INTROSPECTION_FAILED' or pg error code
          details: { message }
        }
        ```

**CRITICAL -- Response shape mapping (Pitfall 4 from research):**
The `IntrospectionService.introspectTable()` returns `{ table_name, table_comment, columns, constraints }`. The API response MUST use `{ entity, columns, constraints }`:
- Rename `table_name` to `entity`
- Omit `table_comment`
- Keep `columns` and `constraints` as-is
