      1. Mock gateway batch endpoint to return { inserted: 3, updated: 7, errors: [] } (upsert behavior)
      2. Send batch of 10 via ArticulosClient
      3. Assert result.inserted === 3, result.updated === 7

    - Test: "partial batch failure does not duplicate successful records on retry" --
      1. First mock: gateway returns 207 with { inserted: 7, updated: 0, errors: [3 errors] }
      2. ArticulosClient sendBatch returns partial result
      3. Verify: result reports 7 inserted, 3 errors -- no inflation

    **Group 2: "Sync State Consistency After Failure"**
    Tests that sync state (lastSyncValue, status) remains consistent when errors occur.
    This validates Phase 10 decisions (preserve lastSyncValue on cancellation, reset to IDLE).

    - Test: "batch processor result reflects accurate counts after mixed batch outcomes" --
      1. Create 3 batches: batch 1 succeeds (10 inserted), batch 2 fails (0 inserted), batch 3 succeeds (10 inserted)
      2. processBatches with continueOnError=true
      3. Assert: result.inserted === 20 (only confirmed batches counted)
      4. Assert: result.failedBatches === 1
      5. Assert: result.successfulBatches === 2

    - Test: "cancellation mid-batch stops processing and reports partial results" --
      1. Mock syncStateManager: returns running for batch 1, canceled for batch 2
      2. Create 3 batches
      3. processBatches
      4. Assert: only batch 1 processed, batches 2 and 3 skipped
      5. Assert: result.errors contains SYNC_CANCELED
      6. Assert: result.success === false

    - Test: "calculateBatchStats reports correct rates" --
      1. Given BatchResult with inserted=8, updated=2, errors=[1 error]
      2. Call calculateBatchStats(result)
      3. Assert: successRate ~= 90.9%, failureRate ~= 9.1%, totalProcessed === 11

    - Test: "mergeBatchResults correctly combines multiple results" --
      1. Create 3 BatchResults with different counts
      2. Call mergeBatchResults(results)
      3. Assert: merged.inserted === sum of all inserted
      4. Assert: merged.updated === sum of all updated
      5. Assert: merged.errors.length === sum of all errors
      6. Assert: merged.success === false if ANY result had success=false

    **Group 3: "Error Classification Drives Retry Decisions"**
    Integration-level test that verifies error classification flows correctly into retry logic.
