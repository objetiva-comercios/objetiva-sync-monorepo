  <files>

  <action>
    1. Install nock as dev dependency in objetiva-sync:
       ```
       cd objetiva-sync && npm install --save-dev nock
       ```
       Note: nock 14.x supports native fetch via @mswjs/interceptors. If nock 14 is not available, use nock 13.x which also works with undici's fetch.

    2. Create `tests/integration/helpers/gateway-mock.ts`:
       - Export `mockGatewayAuth(gatewayUrl: string)`: Sets up nock interceptor for POST /auth/login that returns `{ success: true, token: 'test-jwt-token' }`. Use `.persist()` so auth works for multiple requests in a test.
       - Export `mockGatewayBatchEndpoint(gatewayUrl: string, entityPath: string, response: object, statusCode?: number)`: Sets up nock interceptor for POST `/api/{entityPath}/batch` with configurable response and status code. Default: 200 with `{ success: true, data: { inserted: N, updated: 0, errors: [] } }`.
       - Export `mockGatewayHealth(gatewayUrl: string, statusCode?: number)`: Mocks GET /health endpoint.
       - Export `cleanupMocks()`: Calls `nock.cleanAll()` and `nock.restore()` if needed.
       - IMPORTANT: nock intercepts Node.js HTTP/HTTPS. The project uses undici's fetch. nock 14+ supports this natively. For nock 13.x, you may need to use undici's MockAgent instead. Check the installed nock version and adapt accordingly. If nock does NOT intercept undici fetch, pivot to using undici's built-in MockAgent/MockPool from the `undici` package (already installed) for HTTP mocking. The ArticulosClient constructor already accepts an optional `dispatcher?: Dispatcher` parameter specifically for testing. Create MockAgent/MockPool interceptors if nock doesn't work with undici.
       - Export type `GatewayMockOptions` for configuring mock behavior.

    3. Create `tests/integration/helpers/test-fixtures.ts`:
       - Import actual Zod schemas from the project's type files (e.g., `articuloPayloadSchema` from `src/types/articulos.ts`).
       - Export `createArticuloFixture(overrides?)`: Returns valid IArticuloPayload with realistic test data. Fields: sku, erp_codigo, nombre, objeto (at minimum -- check the actual articuloPayloadSchema for required fields).
       - Export `createCabeceraFixture(overrides?)`: Returns valid IComprobanteCabeceraPayload.
       - Export `createDetalleFixture(overrides?)`: Returns valid IComprobanteDetallePayload.
       - Export `createPagoFixture(overrides?)`: Returns valid IComprobantePagoPayload.
       - Each fixture must pass its corresponding Zod schema validation (this is the test of schema correctness).
       - Export `createBatchFixture(entityType, count)`: Creates array of N fixtures for given entity type.

    IMPORTANT: Before creating fixtures, READ the actual Zod payload schemas in src/types/ to understand exact required fields. Do NOT guess field names.
  </action>
  <verify>
    1. `cd objetiva-sync && npm ls nock` shows nock installed
    2. `npx tsc --noEmit tests/integration/helpers/gateway-mock.ts tests/integration/helpers/test-fixtures.ts` compiles without errors (or use tsx to verify imports work)
    3. Create a quick smoke test: import fixtures, validate each against their Zod schema, confirm all pass
  </verify>
