# Phase 18 Plan 01: Centralized .env Writer with Async Mutex Summary

**One-liner:** Promise-chain mutex env-writer with double-quoting that fixes the ENV-04 special character escaping bug.

## What Was Built

`src/utils/env-writer.ts` — centralized .env writer that replaces all 4 scattered inline .env write locations in the gateway. Exports:

- `writeEnvVar(key, value)` — writes a single key atomically
- `writeEnvVars(vars)` — writes multiple keys in one lock acquisition

Key behaviors:
- Values are always double-quoted: `KEY="value"` — this fixes ENV-04 where `$` and `#` in passwords caused silent corruption
- Inner double-quotes escaped as `\"`, backslashes as `\\`
- Line regex anchored to `^KEY=` with `m` flag — prevents `KEY=` from replacing `APP_KEY=`
- File created with `# .env — Generated by Objetiva Sync Gateway\n` header if it doesn't exist
- `process.env[key]` updated immediately after write (hot-update, no restart needed)
- Mutex chain resets on `doWrite` failure — subsequent writes are not permanently blocked

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test cwd patch ordering in first test**
- **Found during:** GREEN phase (12/13 tests passed on first run)
- **Issue:** First test set `process.cwd = () => tmpDir` before import, then restored cwd before the `await writeEnvVar()` call. Since `doWrite` calls `process.cwd()` lazily at write time, the path was already restored to the real cwd when the write happened — file went to the wrong location.
- **Fix:** Added `vi.resetModules()` before import; wrapped `writeEnvVar` call in `try/finally` to keep cwd patched for the duration of the call
- **Files modified:** `tests/unit/env-writer.test.ts` (first test only)
- **Commit:** `be4dc2f` (included in GREEN commit)
