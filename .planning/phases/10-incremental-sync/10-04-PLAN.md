**Documentation (docs/incremental-sync.md):**

Create `objetiva-sync/docs/incremental-sync.md` in Spanish (project language). Structure:

1. **Titulo**: Sincronizacion Incremental - Guia de Configuracion
2. **Que es**: Brief explanation that incremental sync only fetches records modified since last successful sync
3. **Como funciona**:
   - First sync is always full (no stored timestamp)
   - After successful sync, lastSyncValue is stored per query
   - Subsequent syncs pass `@lastSync` parameter to SQL query
   - Clock skew protection: 5-minute overlap window subtracted from stored timestamp
   - Gateway upsert ensures idempotent processing (duplicates are safe)
4. **Configuracion de queries**:
   - Each query needs an `incrementalField` configured (the column name that tracks modification time, e.g., `fecha_modificacion`, `updated_at`)
   - The SQL query must include a WHERE clause using the `@lastSync` parameter
   - Example SQL: `SELECT * FROM articulos WHERE fecha_modificacion > @lastSync`
   - If `incrementalField` is empty, the query always runs as full sync
   - The `@lastSync` parameter name is case-sensitive and must be exactly `@lastSync`
5. **Sincronizacion completa (override)**:
   - Check "Sincronizacion Completa" checkbox in dashboard before starting sync
   - This ignores stored timestamps and fetches all records
   - Useful after schema changes or data corrections
6. **Proteccion contra clock skew**:
   - System subtracts 5 minutes from stored timestamp
   - This catches records modified during the previous sync window
   - Duplicates are safe because gateway uses upsert (createMany with conflict handling)
7. **Comportamiento en caso de fallo**:
   - If sync fails, timestamps are NOT updated
   - Next sync re-fetches everything since last SUCCESSFUL sync
   - No data loss possible due to idempotent processing
8. **Dashboard**:
   - Badge shows INCREMENTAL or COMPLETA for each sync run
   - "Estado por Entidad" table shows per-query last sync timestamps
   - "Historial de Sincronizacion" shows recent runs with type, counts, duration

Keep it concise and practical. Target 60-100 lines. No enterprise fluff.
