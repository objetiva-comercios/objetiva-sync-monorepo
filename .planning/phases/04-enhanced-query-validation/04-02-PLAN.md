**Step 2: Create schema-validator.ts**

This is a NEW file that complements (not replaces) the existing query-validator.ts. The existing validator uses static Zod schemas; this one uses live gateway schemas.

1. **Import types:**
   - Import { closest, distance } from 'fastest-levenshtein'
   - Import SchemaResponse, ColumnMetadata from '../types/schema.js'
   - Import schemaCache from '../services/schema-cache.js'
   - Import logger from '../utils/logger.js'

2. **ValidationError interface:**
   - field: string (field name that failed)
   - type: 'MISSING_REQUIRED' | 'UNEXPECTED_FIELD' | 'TYPE_MISMATCH'
   - message: string (human-readable error)
   - suggestion?: string (e.g., "Did you mean 'customer_id'?")
   - expectedType?: string (for type mismatches)
   - actualType?: string (for type mismatches)

3. **ValidationResult interface:**
   - isValid: boolean
   - errors: ValidationError[]
   - warnings: string[] (non-blocking issues)
   - schemaUnavailable: boolean (true if gateway was unreachable)

4. **getRequiredFields(schema: SchemaResponse): string[]**
   - Return column names where is_nullable === 'NO' AND column_default === null
   - These are the truly required fields (no default, not nullable)

5. **normalizePostgresType(dataType: string): string**
   - Map PostgreSQL types to JavaScript type expectations:
     - 'varchar', 'text', 'char' -> 'string'
     - 'int', 'integer', 'bigint', 'smallint' -> 'number'
     - 'decimal', 'numeric', 'real', 'double precision' -> 'number'
     - 'boolean' -> 'boolean'
     - 'timestamp', 'date', 'time' -> 'string' (ISO format)
     - 'jsonb', 'json' -> 'object'
     - 'ARRAY' or contains '[]' -> 'array'

6. **detectJsType(value: unknown): string**
   - null/undefined -> 'null'
   - Array.isArray -> 'array'
   - typeof for primitives

7. **isTypeCompatible(jsType: string, pgType: string): boolean**
   - Check if JavaScript value type is compatible with PostgreSQL type
   - Be lenient: 'string' is compatible with 'number' (could be stringified number)
   - 'null' is compatible with nullable fields
   - Return true for 'object' type with 'jsonb'

8. **findSuggestion(fieldName: string, validFields: string[]): string | undefined**
   - Use closest() from fastest-levenshtein to find closest match
   - Use distance() to get edit distance
   - Only suggest if distance <= 3 (catches typos, not unrelated words)
   - Only suggest if field length ratio is between 0.5 and 2.0
   - Return undefined if no good suggestion found

9. **validateQueryAgainstSchema(rows: Record<string, unknown>[], entity: string): Promise<ValidationResult>**
   - Get schema from schemaCache.getSchema(entity)
   - If schema is null, return { isValid: true, errors: [], warnings: ['Schema unavailable, validation skipped'], schemaUnavailable: true }

   **IMPORTANT: Handle empty rows as WARNING, not error:**
   - If rows is empty (rows.length === 0), return:
     ```typescript
     {
       isValid: true,  // NOT false - empty is valid, just nothing to validate
       errors: [],
       warnings: ['Query returned no rows - validation skipped. This may be expected for filtered queries.'],
       schemaUnavailable: false
     }
     ```
   - Rationale: Filtered queries (e.g., WHERE fecha > '2025-01-01') may legitimately return 0 rows. This should not block saving.

   **Validation logic (using first row as sample):**

   a) **Check for missing required fields:**
      - For each required field from getRequiredFields(schema)
      - If not in firstRow, add MISSING_REQUIRED error with suggestion

   b) **Check for unexpected fields:**
      - For each field in firstRow
      - If not in schema.columns (by column_name), add UNEXPECTED_FIELD error with suggestion

   c) **Check for type mismatches:**
      - For each field in firstRow that IS in schema
      - Get expected type from normalizePostgresType(column.data_type)
      - Get actual type from detectJsType(firstRow[field])
      - If not compatible and value is not null, add TYPE_MISMATCH error

   **Return ValidationResult with aggregated errors**

Export: ValidationError, ValidationResult, validateQueryAgainstSchema

   ```typescript
   const activeConnection = await getActiveConnectionConfig();

   if (activeConnection) {
     // Execute a limited test query to get sample data
     // NOTE: Uses SQL Server TOP syntax. For other databases, use LIMIT clause.
     // This is a known limitation - validation assumes SQL Server dialect.
     const testQuery = sqlQuery.trim().toUpperCase().startsWith('SELECT')
       ? sqlQuery.replace(/SELECT/i, 'SELECT TOP 10')
       : sqlQuery;

     let testRows: Record<string, unknown>[] = [];
     try {
       const result = await executeQueryOnConnection(
         activeConnection.adapterType,
         activeConnection.config,
         testQuery
       );
       testRows = result.rows as Record<string, unknown>[];
     } catch (queryError) {
       // Query execution failed - this is a different error than validation
       logger.error({ error: queryError }, 'Query execution failed during validation');
       return reply.status(400).send({
         success: false,
         error: 'Query execution failed: ' + (queryError instanceof Error ? queryError.message : String(queryError)),
       });
     }

     // Validate against schema
     const validation = await validateQueryAgainstSchema(testRows, entityType);

     if (!validation.isValid) {
       // Log validation failure
       logger.warn({ entityType, errors: validation.errors }, 'Query validation failed');

       return reply.status(400).send({
         success: false,
         error: 'Query validation failed against schema',
         validationErrors: validation.errors.map(err => ({
           field: err.field,
           type: err.type,
           message: err.message,
           suggestion: err.suggestion,
         })),
       });
     }

     // Log warnings (empty rows, schema unavailable) but allow save to proceed
     if (validation.warnings.length > 0) {
       logger.info({ entityType, warnings: validation.warnings }, 'Query validation passed with warnings');
     }

     // Log if schema was unavailable (but validation passed by default)
     if (validation.schemaUnavailable) {
       logger.warn({ entityType }, 'Schema unavailable during validation, proceeding without schema check');
     }
   } else {
     logger.warn('No active connection - skipping query validation');
   }
   ```
