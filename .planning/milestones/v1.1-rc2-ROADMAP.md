# Milestone v1.1-rc2: Multi-Source & Hardening

**Status:** ✅ SHIPPED 2026-02-18
**Phases:** 13-16
**Total Plans:** 14

## Overview

This milestone enabled multi-origin synchronization by adding PostgreSQL as a data extraction source alongside SQL Server, implemented origin tracking for audit trails, simplified authentication workflows, and added production observability. Phase 17 (Dashboard Modernization with shadcn/ui) was implemented but rolled back due to issues.

## Phases

### Phase 13: PostgreSQL Adapter

**Goal**: Users can configure and execute sync queries against PostgreSQL databases using the same workflow as SQL Server.
**Depends on**: Nothing (foundation phase)
**Plans**: 2 plans

Plans:
- [x] 13-01-PLAN.md - PostgreSQL Adapter Core (adapter implementation, pg dependency, registry)
- [x] 13-02-PLAN.md - PostgreSQL UI & Integration (SSL fields in UI, integration tests)

**Details:**
- PostgreSQLAdapter extends AbstractAdapter, implements IDataSourceAdapter
- Uses `pg` library with pool-based connection management
- Connection config stored in SQLite alongside SQL Server configs
- Dashboard connection form extended for PostgreSQL-specific SSL fields
- 22 unit tests covering adapter interface compliance

---

### Phase 14: Multi-Source Origin Tracking

**Goal**: Gateway tracks which data source wrote each record, enabling audit trails and last-write-wins conflict resolution.
**Depends on**: Phase 13
**Plans**: 3 plans

Plans:
- [x] 14-01-PLAN.md - Origin Tracking Schema & Migration
- [x] 14-02-PLAN.md - Source ID Generation & Header Propagation
- [x] 14-03-PLAN.md - Conflict Detection & Integration Tests

**Details:**
- Prisma schema migration adds origin_source, origin_sync_id, origin_synced_at to all entity tables
- Ingestion service extracts X-Origin-Source header from requests
- Sync module sends origin header with each batch
- sync_state table extended with sourceId column for per-source watermarks
- Conflict detection compares origin_synced_at within 5-minute overlap window

### Phase 15: Auth Simplification

**Goal**: Users can set up and troubleshoot authentication without manual bcrypt hash generation or guessing at error causes.
**Depends on**: Nothing (independent)
**Plans**: 4 plans

Plans:
- [x] 15-01-PLAN.md - Token refresh endpoint and specific auth error codes
- [x] 15-02-PLAN.md - Auth diagnostics and password change endpoints
- [x] 15-03-PLAN.md - Client-side token refresh in AuthManager
- [x] 15-04-PLAN.md - Integration tests and verification

**Details:**
- POST /auth/refresh endpoint issues new token before expiration
- AuthManager in sync module calls refresh proactively
- GET /api/auth/diagnostics exposes non-sensitive token metadata
- POST /api/auth/change-password requires current password verification
- 21 integration tests covering all auth features
- Error codes: TOKEN_EXPIRED, TOKEN_INVALID, TOKEN_MISSING, SIGNATURE_MISMATCH

## Milestone Summary

**Key Decisions:**
- POSTGRES-01: Use pg library Pool for connection management
- POSTGRES-02: Convert @param/:param to $1 positional parameters
- ORIGIN-01: Origin columns nullable for backwards compatibility
- ORIGIN-03: Conflict detection is best-effort (doesn't block ingestion)
- AUTH-03: Refresh-first token strategy with login fallback
- HEALTH-01: Gateway critical, scheduler optional in sync health
- PROM-01: Custom Registry to avoid default registry pollution

**Issues Resolved:**
- Multi-source sync now works with PostgreSQL alongside SQL Server
- Long-running syncs no longer expire tokens
- Auth errors provide specific troubleshooting information
- Health probes enable Kubernetes integration
- Correlation IDs enable end-to-end request tracing

**Issues Deferred:**
- Dashboard modernization (Phase 17 rolled back, revisit in future milestone)
- Setup wizard (AS-04 partially implemented)

**Technical Debt Incurred:**
- Phase 17 code removed but some shadcn dependencies may remain
- HTMX dashboard is functional but lacks origin/metrics visualization
