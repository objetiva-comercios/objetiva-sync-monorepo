## Goal

PostgreSQL schema changes propagate correctly through the entire synchronization pipeline without breaking queries, validation, or data ingestion.

## Accomplishments

### Phase 1: Schema Introspection Foundation (2026-01-27)
- Built IntrospectionService querying PostgreSQL information_schema and pg_catalog
- Type normalization system mapping PostgreSQL types to simplified standards
- Retry logic with exponential backoff for connection resilience
- Configurable database pool (max 5 connections, 5s statement timeout)

### Phase 2: Schema Distribution Endpoint (2026-01-27)
- GET /api/schemas and /api/schemas/:entity with JWT authentication
- In-memory schema cache with 1-hour TTL (1-2ms cache hit, ~35ms cache miss)
- Entity whitelist validation preventing arbitrary table exposure

### Phase 3: CLI Code Regeneration (2026-01-30)

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| PostgreSQL as single source of truth | Destination schema is what matters for data integrity |
| Gateway exposes schemas via HTTP | Sync runs on different server, needs remote access |
| Manual regeneration command | User controls when to propagate schema changes |
| 1-hour cache TTL | Balance freshness vs database load |
| Levenshtein distance <= 3 | Catches typos without unrelated suggestions |
| Native Fastify SSE | Simpler than plugins, well-supported |
| Sequential entity processing | Prevents database pool exhaustion |
