# Reglas y Procedimientos del Proyecto Objetiva Sync

## Flujo de Git
- Hacer push a Git después de cada cambio importante o completar una funcionalidad
- Escribir mensajes de commit claros y descriptivos
- Crear ramas para nuevas funcionalidades o cambios significativos

## Registro de Actividad
- Mantener un archivo `ACTIVIDAD.md` con entradas con fecha y hora
- Registrar todas las decisiones importantes, cambios e implementaciones
- Consultar este registro cuando se necesite contexto o continuidad

## Comunicación
- Pedir confirmación antes de implementar cambios que rompan compatibilidad
- Proponer decisiones arquitectónicas antes de implementarlas
- Presentar alternativas cuando existan múltiples enfoques
- Señalar posibles problemas o deuda técnica

## Gestión de Tareas
- Mantener un archivo `PENDIENTES.md` con tareas priorizadas
- Actualizar PENDIENTES después de completar tareas
- Agregar nuevas tareas a medida que surjan durante el desarrollo

## Calidad de Código
- Escribir código limpio y legible con estilo consistente
- Agregar comentarios solo para lógica compleja
- Preferir soluciones simples sobre soluciones ingeniosas
- Seguir los patrones y convenciones existentes del proyecto

## Pruebas
- Probar funcionalidad crítica antes de hacer commit
- Reportar cualquier error o problema inmediatamente
- Validar que los cambios funcionen como se espera

## Documentación
- Actualizar README.md al agregar funcionalidades
- Documentar cambios en la API en API.md
- Mantener actualizada la documentación en DATABASE.md y ARQUITECTURA.md

## Archivos de Referencia
- Consultar `DATABASE.md` para detalles completos del modelo de datos
- Consultar `ARQUITECTURA.md` para patrones, estructura y tecnologías
- Revisar `DECISIONES.md` antes de tomar decisiones arquitectónicas
- Actualizar `API.md` al crear o modificar endpoints
